# Docs

How the coach works and why, for anyone working on it: developers, and the learning designers who write its content.

- `design.md`: how the coach gives feedback, and the reasoning and research behind it.
- `experience.md`: what the learner sees and does, step by step.
- `rubric.md`: what the coach judges, and when a response counts as strong.
- `evals.md`: how the evals work, how to run them, and how to read the results.

Planned, written with the code it describes:

- `architecture.md`: how the app is put together: the model calls, the rules applied in code, data handling and security.

## Reference

The research the design draws on, each gathered by a research agent. Findings and inferences are marked, and the citations were not individually re-checked.

- `reference/research-the-situation.md`: what business ethics, professional codes and organizational behaviour research say about the dilemma in the scenario.
- `reference/research-feedback-pedagogy.md`: what learning science says about feedback on open-ended reasoning, including AI-generated feedback.
- `reference/research-experience-design.md`: branching scenarios, consequence-based feedback and AI role-play, and a map of the design space.
